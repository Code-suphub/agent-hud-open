# Custom balance sources

Settings → **Balance sources** can monitor an HTTPS JSON query independently of the installed AI clients. It does not change model prices or infer which local calls belong to the remote account.

1. In the service's browser developer tools, find its **read-only balance or quota query**, then choose **Copy as cURL**.
2. Choose **Add source**, enter a name and currency/unit, paste the request, and select **Parse cURL**. Choose which headers and individual cookies to retain, and mark the headers that should be editable when authentication expires. Browser metadata (`User-Agent`, `Accept-Encoding`, `Sec-*`, etc.) starts unchecked. `Origin` and `Referer` can be explicitly retained for services requiring them. Then choose **Request and inspect fields**; the test uses the selected request.
3. Select a numeric balance field and, optionally, its total. For services exposing used amounts, select **Used amount (total − used)** and map both fields. The preview shows the result before saving. A divisor converts the endpoint's raw units (use `1` without conversion).

The picker lists JSON Pointer paths and numeric values, including numeric strings and nested array elements. `/data/remaining` and `/data/total` are common examples. Field names containing `/` and `~` are escaped as `~1` and `~0`. Boolean values never become money. Missing fields and invalid conversions fail the reading instead of becoming a zero balance.

Saved sources appear as API balance cards in the hover panel: **Remaining**, **Total**, and a consumption bar when the total is positive. The balance's own observations can provide an exhaustion estimate after at least three hours of declining readings. Totals come directly from the selected response; they are not estimates based on local token prices. Choose the endpoint's actual currency/unit, such as `USD`, `CNY`, or `CREDITS`; credit amounts are not converted to money.

The collector queries enabled sources approximately every five minutes (plus its normal request spread). **Refresh now** uses the same account request spacing as other sources. Pausing or removing a source stops further scheduled requests. A failed read retains the last successful amount and its observation time, marked as a failed reading; it does not present an old value as newly confirmed. Changing the field mapping or units starts a separate balance trend.

HTTP 401/403, a redirect to a recognized sign-in path, and explicit JSON authentication status codes 401/403 open a nonmodal credential window near the HUD. These failures pause background retries until credentials are changed. Network errors, other HTTP errors, and missing fields do not open credential prompts. A prompt appears once per failed-authentication episode; **Later** dismisses it without repeated popups. The affected hover card retains **Update credentials**, and Settings offers the same action beside each source. Removing or disabling a source closes its pending prompt; recovery clears the reminder so a later expiry can notify again. Multiple failures wait one at a time, independently of agent approval requests.

A source can store an optional HTTPS website or sign-in page. The source list and renewal window open that page in the default browser. You can edit the website on an existing source without retesting its query. After signing in, paste the updated credentials into the renewal form.

The renewal window contains only the selected credential header names, with blank secure inputs. Blank fields preserve existing values. For Cookie updates, only originally selected cookie names are replaced; unrelated browser cookies are ignored. A raw bearer token keeps the saved `Bearer` prefix automatically. **Verify and update** validates the selected balance/total mappings before atomically replacing the local request file, then resumes account collection immediately. Failed verification leaves saved credentials unchanged. For authentication in query/body values, or changed endpoint or cookie names, use **Settings → Edit** to import a new cURL and test its allowlist.

The HTTP request—including its URL, headers, cookies and body—is saved as local JSON under `~/Library/Application Support/Agent HUD Open/balance-requests/`. The directory is owner-only (`0700`) and each request file is owner-readable/writable (`0600`); updates use an atomic rename and reject symbolic links. Settings store source details such as names, units, field paths, request identifiers and the optional website. Reports and the ledger contain readings, never the saved request. This storage does not use Keychain or enable any cloud synchronization. Earlier development builds kept requests in Keychain; import each request once when moving from those builds. The new application does not open Keychain automatically to migrate old entries. Browser cookies are not scraped automatically or shared implicitly with the app.

Daily balance displays, including the small hover peek and the menu, use at most two fractional digits. The **currency/unit** field accepts ISO currencies such as `CNY` and `USD` as well as custom units such as `CREDITS`; noncurrency values use decimal formatting instead of the system currency formatter. The divisor controls actual unit conversion independently of the label. Selecting CNY does not establish a credit-to-yuan exchange rate.

Click a source's avatar in Settings → Balance sources to choose a local PNG/JPEG/WebP image or Emoji and enable its motion. Images are normalized to a small PNG and kept in local settings. Custom artwork retains its original appearance and uses the existing agents' hop/breathing motion; it follows the global bot setting and Reduce Motion. Disabling animation keeps a still avatar. Restoring the default restores the name's initial. Avatar edits do not change quota identity or require another credential import. Built-in agent names retain their bundled artwork.

The importer parses cURL **as data**; it never invokes a shell. It accepts one HTTPS URL, GET/POST, literal `-H` / `--header`, `-b` / `--cookie`, and one inline `--data` / `--data-raw` / `--data-binary` body. Browser formatting such as line continuations and `--compressed` is supported. Other options, file reads, shell expressions, insecure transport, and redirects are rejected. Requests use an ephemeral session, no shared cookie or credential store, a 20-second resource timeout and a 2 MB response limit. Only configure read-only queries, even when they use POST.
